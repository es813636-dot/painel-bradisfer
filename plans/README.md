## Recommended execution order

Each plan's steps describe the insertion point relative to what's there *before* that plan runs, so applying them out of order — or applying 002/004 against a tree that hasn't had 001's insertion yet, or vice versa — will change exactly where "immediately after" lands. Executing them in numeric order avoids this; if you must run them out of order or in parallel worktrees, each executor should locate its insertion point by re-reading the current file content (per each plan's Boundaries: "if a cited line doesn't match, STOP and report") rather than trusting the line numbers verbatim.
